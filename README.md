# zbs-booking

Сторінка запису для малого бізнесу. З одного коду виходить і **демо** під
конкретний заклад (для листа, нічого нікуди не шле), і **бойова** версія
(справжній запис і повідомлення).

## Швидкий старт

```bash
npm test          # 20 тестів логіки, без залежностей
npm run build     # зібрати всі профілі з clients/ у dist/
npm run build -- mega-servis   # тільки один
```

Результат: `dist/<slug>/index.html` — **один самодостатній файл**.
Ніякого рантайму, ніяких залежностей, ніякого CDN, крім шрифтів.

## Зробити демо під новий заклад

1. `cp clients/_template.json clients/<slug>.json`
2. Заповнити: назва, адреса, години, послуги з їхнього ж прайсу
3. `npm run build -- <slug>`
4. Викласти `dist/<slug>/` на GitHub Pages

Докладніше: [`docs/NEW-CLIENT.md`](docs/NEW-CLIENT.md) · [`docs/DEPLOY.md`](docs/DEPLOY.md)

## Чому саме так

Див. [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md). Коротко: демо і бойова
версія — це **один і той самий код** з різними адаптерами даних. Демо не
викидається після продажу, воно стає продуктом. Тому те, що клієнт побачив
у листі, і те, що він отримає, не можуть розійтись.

## Нуль залежностей

`package.json` не має `dependencies` і не матиме. Ми продаємо надійність —
збірка, яка ламається від чужого оновлення, суперечить самому продукту.
